# Этап 2: добавление слов с сайта в Google Sheets

## Что подготовлено

- `index.html` — актуальный файл из main репозитория alehors-srs/Baozi с обновлённой формой добавления.
- `apps-script/Code.gs` — обработчик для Google Apps Script. Его нужно вставить в редактор Apps Script, а не в index.html.
- `tests/` — локальные проверки; загружать их на сайт не требуется.

Пароля и входа на сайте нет. Опубликованный обработчик принимает добавление от любого отправителя. Указанный origin служит для доставки ответа в браузер и не является проверкой доступа.

Рабочая таблица уже указана в коде:
https://docs.google.com/spreadsheets/d/1WftxEklWgb28mGFGU0CRt-0K-n8VqR2OrzpZZXI-PXQ/edit

Лист: `words`. Запись в `names` в этот этап не включена.

## 1. Создайте Apps Script при таблице

1. Откройте таблицу под Google-аккаунтом, которому разрешено её редактировать.
2. Выберите **Расширения → Apps Script**. Если открывается существующий проект с другими функциями, создайте отдельный проект Apps Script, чтобы не заменить чужой код.
3. В новом проекте замените содержимое стандартного файла Code.gs (или Код.gs) текстом из `apps-script/Code.gs` из архива.
4. Сохраните проект, например под названием `Baozi — добавление слов`.
5. В листе words первая строка должна содержать ровно три колонки: `char`, `pinyin`, `translation`. Порядок колонок может отличаться. Скрипт использует заголовки и ничего в существующих строках не исправляет.

## 2. Опубликуйте веб-приложение

1. В редакторе Apps Script нажмите **Развернуть / Deploy → Новое развёртывание / New deployment**.
2. Выберите тип **Веб-приложение / Web app**.
3. **Выполнять от имени / Execute as:** ваш аккаунт (**Me**).
4. **У кого есть доступ / Who has access:** **Все / Anyone**, включая пользователей без входа в Google. Режим «любой пользователь с аккаунтом Google» для этой формы не подходит.
5. Нажмите **Развернуть**, проверьте и подтвердите запрошенный доступ к своей таблице.
6. Скопируйте URL веб-приложения вида `https://script.google.com/macros/s/…/exec`.

Если варианта Anyone нет, публикация может быть ограничена политиками вашего Google Workspace. Потребуется разрешённый аккаунт/настройка администратора; на сайте такой режим нельзя исправить заменой JavaScript.

Открытие полученного URL в браузере должно показывать: «Baozi: сервис добавления слов готов…». Само открытие URL не добавляет строк.

При последующем изменении Code.gs обновляйте опубликованную версию: **Развернуть → Управление развёртываниями → Изменить → Новая версия → Развернуть**. Простого сохранения кода недостаточно для обновления /exec.

## 3. Подключите URL к сайту

В новом `index.html`, строка **1471**, замените:

```javascript
const GOOGLE_SHEETS_WEB_APP_URL = '';
```

на свою ссылку:

```javascript
const GOOGLE_SHEETS_WEB_APP_URL = 'https://script.google.com/macros/s/ВАШ_ИДЕНТИФИКАТОР/exec';
```

Вставьте реальную ссылку из развёртывания, без пробелов и без фрагмента `/dev`. Не вставляйте сюда ссылку на таблицу, CSV или редактор Apps Script.

По умолчанию ответы направляются на origin `https://alehors-srs.github.io`. Сайт должен открываться на https://alehors-srs.github.io/Baozi/. Для другого домена нужно согласованно поменять `siteOrigin` в Code.gs и проверку `location.origin` в index.html, затем обновить развёртывание Apps Script. Открытие index.html с диска не поддерживает добавление в Google Sheets.

## 4. Загрузите index.html

1. В GitHub замените только `index.html` в корне `alehors-srs/Baozi`, ветка main, файлом из архива с уже заполненным URL.
2. Дождитесь успешного workflow публикации сайта.
3. Обновите сайт. Если браузер использует старую страницу из service worker, закройте вкладку и откройте снова; после фонового обновления кеша может понадобиться ещё одна перезагрузка.

Не заменяйте sw.js, words.js, names.js, manifest.json или workflow ради этого изменения. Изображения и шрифты также не меняются. Файлы Code.gs и tests загружать в репозиторий для работы формы не нужно.

## 5. Проверьте на реальной таблице

1. В разделе «Словарь» заполните новое слово, пиньинь и перевод. Кнопка теперь называется **«Добавить в Google Sheets»**.
2. Нажмите её один раз. Во время запроса поля и кнопки формы временно отключаются.
3. При подтверждённой записи появится зелёное сообщение **«Слово сохранено в Google Sheets и локально»**. Проверьте новую строку в таблице. Если localStorage браузера недоступен, сообщение отдельно скажет, что слово записано в таблицу, но локальная копия не сохранилась.
4. Введите те же три значения повторно. Должно появиться сообщение о наличии слова в Google Sheets; лишней строки быть не должно. Форма останется заполненной для редактирования.
5. Тот же иероглиф с другим переводом или пиньинем разрешён как отдельная запись.
6. Дождитесь очередной синхронизации GitHub либо запустите существующий workflow вручную, чтобы слово попало в общий words.js. Опубликованный Google CSV может обновляться с задержкой; если новый строки ещё нет в CSV, повторите синхронизацию позже.

При тайм-ауте сообщение **не утверждает, что запись не состоялась**: она могла попасть в таблицу, но подтверждение не дошло. Проверьте таблицу или повторите отправку — повтор проходит ту же проверку дубля.

## Как проверяются повторы

Сервер читает текущие данные Google Sheets, не опубликованный CSV и не словарь браузера. Проверка и добавление выполняются под `LockService.getScriptLock()`.

Совпасть должны все три поля. Для сравнения не учитываются регистр, пробелы по краям, повторяющиеся пробелы, невидимые символы и различие старых breve-тонов пиньиня (nĭ) и caron-тонов (nǐ). Различающиеся переводы/произношения сохраняются отдельно. Пробелы между слогами, знаки препинания и отличия в формулировке перевода не считаются синонимами автоматически.

Блокировка защищает запросы этого Apps Script между собой. Ручные правки таблицы и другие скрипты, не использующие эту блокировку, она не блокирует.

Сервер проверяет длину и обязательность полей, очищает невидимые символы и лишние пробелы. Значения записываются как текст, чтобы перевод, начинающийся с `=`, не исполнялся как формула. Максимум: char — 100, pinyin — 300, translation — 2000 символов.

Существующие локальные слова и их загрузка сохранены. Наличие слова только в браузере не блокирует запись в таблицу. После ответа сервера локальная копия добавляется без повтора. Ранее сохранённые локальные слова не загружаются в таблицу автоматически — их можно отправить через форму по одному.

Для новой записи теперь требуется подтверждение Google Sheets. При отсутствии подключения, ошибке сервера или тайм-ауте поля сохраняются; новая локальная запись автоматически не создаётся. Старые локальные слова остаются на устройстве.

## Технические детали и проверки

Форма делает POST в скрытый iframe. Apps Script отправляет подтверждение через postMessage. Это позволяет получить явный результат без непрозрачного fetch-ответа `no-cors`. Сайт проверяет HTTPS-origin Google, тип сообщения и случайный 128-битный requestId. Сам факт загрузки iframe не считается успехом. Запись в Google Sheets не выполняется через GET.

Изменения в исходном index.html:
- Строка 431: название кнопки.
- Строка 435: доступный статус role=status и aria-live.
- Строки 1470–1535 исходной версии: заменён обработчик добавления; новая конфигурация URL, транспорт подтверждения и локальное сохранение без дубля.
- Остальные участки index.html сохранены. База: main, blob bc4ae752f6b0d8f1ffe9639fc0a86e97d1a1acd7.

Запуск проверок из корня распакованного архива (Node.js):

```bash
node tests/backend.test.cjs
node tests/frontend.test.cjs
```

Проверки используют имитацию Google Sheets/DOM и не добавляют слова в вашу таблицу. Пройдены 10 серверных и 8 клиентских сценариев: обычное добавление, дубли и нормализация, другой перевод/пиньинь, перестановка колонок, текст вместо формул, ошибки схемы, блокировка, некорректные запросы, HTML-экранирование, ожидание подтверждения, защита от двойного нажатия, посторонние сообщения, тайм-аут и недоступность localStorage.

Живое подключение требует публикации Apps Script в вашем аккаунте и проверки по шагу 5. В предоставленном index.html URL намеренно оставлен пустым: он появится только после вашего развёртывания.
