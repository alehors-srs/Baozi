# Baozi: Google Sheets → GitHub → сайт

Подготовлено для https://github.com/alehors-srs/Baozi, ветка main.

## Состав

- `.github/workflows/sync-dictionaries.yml` — запуск раз в час, на 17-й минуте, вручную и при изменениях main; синхронизация, коммит и публикация сайта.
- `scripts/sync_dictionary.py` — загрузка двух опубликованных CSV и генерация словарей; Python 3.12, без сторонних библиотек.
- `tests/test_sync_dictionary.py` — проверки CSV и сохранности файлов при ошибках; workflow запускает их перед синхронизацией.
- `sw.js` — версия присланного service worker с приоритетом сети для словарей и резервной копией для офлайн-работы. В репозитории на момент проверки sw.js отсутствовал, хотя index.html уже регистрирует его.
- `words.js`, `names.js` — результат проверенной загрузки ваших таблиц: 177 слов и 12 имён.

`index.html` менять не нужно: его версия в репозитории побайтово совпадает с приложенной и уже подключает оба словаря и sw.js. Изображения, шрифты и manifest.json остаются в репозитории.

## Установка через GitHub Desktop

1. Откройте репозиторий Baozi на GitHub → Settings → Pages → Build and deployment → Source → **GitHub Actions**. Настройки нужно поменять один раз.
2. Клонируйте `alehors-srs/Baozi` в GitHub Desktop, переключитесь на main и выполните Fetch/Pull, если локальная копия уже есть.
3. Распакуйте архив. Скопируйте его содержимое в корень локального репозитория с сохранением вложенности `.github/workflows`, `scripts` и `tests`. Включите показ скрытых папок, если `.github` не видна. Замените words.js и names.js. Файл INSTALL_RU.md можно также сохранить в репозитории.
4. Проверьте список изменений в GitHub Desktop. Нажмите Commit to main, затем Push origin. Изменения сайта будут опубликованы этим workflow.
5. На GitHub откройте Actions → **Sync dictionaries and deploy Baozi**. Дождитесь зелёного результата обоих заданий: `sync-and-build` и `deploy`.
6. Для повторной проверки нажмите **Run workflow**, выберите main и подтвердите запуск. Ссылка на опубликованный сайт появится у задания deploy.

Личный токен GitHub и Google API не нужны: CSV уже опубликованы, запись в репозиторий и публикация используют встроенный GITHUB_TOKEN с разрешениями, указанными в workflow. Не добавляйте токены в Google Sheets, index.html или JS-файлы.

Если main защищена от прямой записи ботов, шаг git push завершится ошибкой. Этот пакет рассчитан на разрешённую запись GITHUB_TOKEN в main; для защищённой ветки нужен вариант с pull request. При ошибке прав также проверьте, разрешены ли GitHub Actions и запись токена политиками репозитория/организации.

## Добавление слов

На обоих листах первая строка содержит ровно три заголовка:

| char | pinyin | translation |
|---|---|---|
| 你好 | nǐ hǎo | привет |

- Лист `words`, gid=0 → words.js → window.dictionary.
- Лист `names`, gid=753580976 → names.js → window.names.
- Можно менять порядок колонок, но названия заголовков должны сохраняться.
- Все три поля каждой непустой строки обязательны. Полностью пустые строки пропускаются.
- Кавычки, запятые и переносы строк в ячейках поддерживаются стандартным CSV-парсером.
- Точные повторы трёх полей убираются с предупреждением в журнале. Разные переводы или пиньинь одного иероглифа сохраняются.
- Пробелы по краям ячеек убираются. Невидимые символы U+200B, U+200C, U+200D, U+2060, U+FEFF и U+00AD удаляются с предупреждением в журнале. Регистр и тоны автоматически не исправляются. В текущем CSV невидимые символы найдены в трёх записях words: 八, 知道 и 幺; в сгенерированном файле они очищены.

Google Sheets — полный источник данных. Редактирование строки изменяет запись, удаление строки удаляет запись. Перед первой синхронизацией в таблице должны быть ВСЕ нужные слова. Локальные пользовательские слова, сохранённые тренажёром в браузере, эта синхронизация не изменяет и в таблицу не переносит.

Проверьте, что в настройках публикации Google Sheets включено автоматическое обновление опубликованных данных. Google может отдавать опубликованный CSV с задержкой. После изменения таблицы дождитесь очередного запуска либо используйте Run workflow. После успешной публикации заново откройте/обновите страницу тренажёра: уже открытая вкладка сама не перечитывает массивы.

GitHub запускает расписание примерно раз в час, на 17-й минуте; точное время не гарантируется. В публичном репозитории после 60 дней без активности GitHub может отключить расписание — при необходимости включите workflow снова в Actions.

## Защита от ошибок и публикация

Перед записью проверяются оба CSV. При недоступной таблице, неправильных заголовках, неполной записи или пустом словаре скрипт завершается с ошибкой, не меняя текущие словари. В журнале указываются лист и строка CSV; при переносах внутри ячеек это номер физической строки CSV.

При отсутствии изменений коммита нет. Запуск по расписанию без изменений также пропускает публикацию. Ручной запуск и push в main публикуют сайт даже без изменений словарей. Поэтому ручной запуск также позволяет повторить публикацию после её сбоя.

Коммит словарей и публикация выполняются в одном workflow: публикация не зависит от запуска другого workflow после коммита бота. При конфликте с параллельной записью git push остановится; workflow не перезаписывает чужие изменения. Повторите запуск после обновления main.

Если загрузка CSV или проверка данных завершилась ошибкой, публикация сайта в этом запуске тоже останавливается. Существующий опубликованный сайт продолжает работать.

## Локальная проверка

Из корня репозитория:

```bash
python -m unittest discover -s tests -v
python scripts/sync_dictionary.py
```

Вторая команда скачивает текущие CSV и обновляет локальные words.js и names.js. После установки редактируйте слова в таблице: ручные правки этих JS-файлов будут заменены при синхронизации.
